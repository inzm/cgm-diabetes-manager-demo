## 1. 目的と基本方針

本計画は、先般実施されたシステム総合品質監査（`system_quality_audit_report.md`）において洗い出された**「表示崩れ」「重大な計算バグ」「Gemini APIの破損」「UIのチープさ」「仕様書記載機能の未実装」**を抜本的に解決し、実用・商用レベルに耐えうる最高品質のヘルスケア管理システムへ昇華させることを目的とします。

### 改善の4大原則
1. **臨床データの正確性最優先**: 誤った投与判断を防止するため、糖質計算バグ（100倍バグ）やマスタ単位の不整合を即座に根絶する。
2. **圧倒的な視覚的クオリティ (WOW Design)**: `#######` 表示や文字クリッピングを排除し、統一デザインシステム（`modUITheme`）に則った美しく洗練されたUI/UXを全画面・フォームに適用する。
3. **仕様適合率 100%**: 仕様書に定義されているが未実装の分析機能、活動イベント登録、設定画面を完全実装する。
4. **安全実行プロセスの遵守**: すべての変更は `safe_excel_runner.py` 経由でコンパイル・動作検証・スクリーンショット確認を行い、Gitによるバージョン管理を徹底する。

## 3. フェーズ別 詳細実装計画

### 【Phase 1】クリティカル修正（緊急バグ・表示破綻の即時解消）

#### 1.1 カレンダー画面の `#######` 解消
- **対象**: `modCalendar.DrawCalendar`, `modCalendar.UpdateCalendarData`, シート `カレンダー`
- **原因**: 列幅が `7.5` であるのに対し、書式 `🍚 0.0"g"` で文字数オーバーが発生。
- **改善策**:
  - カレンダーの列幅（B〜O列）を `7.5` から `8.8` 〜 `9.2` へ最適化。
  - セル内のフォントサイズを `9pt` または `8.5pt` に微調整し、余白を確保。
  - 糖質量が整数（例: `180g`）の場合は小数点以下を表示せず、小数の場合のみ1桁表示するスマート書式を採用。
  - 結果として、200gを超える大量摂取日でも絶対に `#######` が発生しないレイアウトを確立。

#### 1.2 日次詳細画面のサマリー指標セル結合修正
- **対象**: `modDailyDetail.UpdateDailyDetailView`, シート `日次詳細`
- **原因**: `C9:C10` など縦方向1列しか結合されておらず、大フォントの数値（`188 mg/dL`, `190.9 g` 等）が左右でクリッピング（`38 mg/c`, `.90.9 {`）されている。
- **改善策**:
  - セル結合を以下の通り4列ブロック結合に再定義：
    - 血糖値平均: `C8:F8`（見出し）, `C9:F10`（数値表示カード）
    - 糖質総量: `G8:J8`（見出し）, `G9:J10`（数値表示カード）
    - インスリン量: `K8:N8`（見出し）, `K9:N10`（数値表示カード）
    - 異常回数: `O8:Q8`（見出し）, `O9:Q10`（数値表示カード）
  - 数値と単位（`mg/dL`, `g`, `単位`, `回`）を美しく中央配置（`HorizontalAlignment = xlCenter`）し、左右の文字欠けを完全撲滅。

#### 1.3 食事登録時の糖質計算ロジック修正（100倍バグ根絶）
- **対象**: `frmAddMealEvent` (行146〜156)
- **原因**: 食品マスタの基準値（C列: 100g, 200ml等）を無視して `unitCarbs * amount` と直接乗算しているため、100倍の数値が登録される。
- **改善策**:
  ```vba
  ' 修正後の安全な糖質計算ロジック
  Dim baseAmount As Double
  baseAmount = CDbl(foodInfo(2)) ' 食品マスタC列（基準量: 100等）
  If baseAmount <= 0 Then baseAmount = 1
  totalItemCarbs = (unitCarbs / baseAmount) * amount
  ```
  - 食品マスタに基準量（C列）を取得する関数 `GetFoodInfoFromMaster` を拡張。
  - マスタに未登録の食品（例: 「卵焼き」）が食品マスタに欠落しているため、食品マスタに「卵焼き（糖質1.5g / 1人前）」を追加登録し、データ整合性を担保。

#### 1.4 Gemini API連携の完全修復
- **対象**: `modGeminiAPI`, `frmAddMealData`
- **改善策**:
  - **文字化け解消**: UTF-8/CP932のエンコーディング不整合を解消し、正規の日本語プロンプトでコードを再生成。
  - **最新エンドポイント対応**: モデル名を架空の `gemini-2.5-flash` から、Google公式の最新モデル `gemini-1.5-flash` または `gemini-2.0-flash` へ修正。
  - **APIキー管理の分離**: ソースコード内のハードコードを廃止し、ワークブック内の設定シートまたはVBA定数から安全に取得する設計へ移行。
  - **JSON抽出の堅牢化**: 正規表現（`VBScript.RegExp`）を用いて、APIレスポンスから数値を安全かつ確実に抽出するパーサーを実装。
