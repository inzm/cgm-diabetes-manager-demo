# システム仕様書：血糖値・食事・インスリン統合管理システム (Excel VBA)

**最終更新日**: 2026年9月28日  
**対象システム**: `main.xlsm` (Excel VBA / FreeStyleリブレ連携システム)  
**対象バージョン**: 2.0 (データ整合性規約・UIデザインシステム・多角分析統合版)

---

## 1. システム概要と開発目的

### 1.1 解決したい課題・背景
糖尿病や耐糖能異常の管理において、過剰な糖質制限は栄養バランスを崩し別の健康障害を引き起こすリスクがあるため、適切な糖質摂取と適切なインスリン投与のバランス維持が不可欠である。
日々の家庭での食事メニューは多岐にわたり、感覚的なインスリン投与に依存すると、時に**低血糖（70mg/dL未満）**や**高血糖（180mg/dL超）**を招く。
本システムは、連続グルコース測定器（FreeStyleリブレ）の測定データと、食事内容・摂取糖質量・インスリン投与量・身体活動の記録を一元的に統合・可視化し、**適切なインスリン量の決定および食事管理を支援する定量的知見を得ること**を目的とする。

### 1.2 開発および運用の目標
1. **高精度な臨床記録とデータ整合性の完全担保**:
   食事と食事明細の親子関係を厳密に管理し、自動生成される測定ログの客観性を保護する。
2. **直感的かつ洗練されたモダンUI/UX**:
   Excel特有の無骨さを排し、Webダッシュボード風のカード調デザイン・統一されたカラーシステム・スムーズな操作性を実現する。
3. **多角的なデータ分析と将来展望**:
   曜日別・食品別・異常日別の多角的分析ダッシュボードを提供し、将来的なGemini APIによるAI健康分析支援への拡張性を備える。
4. **VBA学習・技術教育・成果発表への対応**:
   体系的で堅牢なモジュール設計、全プロシージャへの分かりやすい解説コメントの付与、成果発表用プレゼンテーション・動画化（Canva/CapCut連携）に対応する完成度を担保する。

## 2. システムアーキテクチャ・画面構成

本システムは、**6つの主要画面（ワークシート）**と、**5つの専用ユーザーフォーム（UserForm）**で構成される。

```
[ main.xlsm ]
 ├── 画面 (Worksheets)
 │    ├── カレンダー       : 月次グリッド表示、日次サマリー、クイック記録ボタン
 │    ├── 日次詳細         : 24時間血糖値推移グラフ(凡例付)、食事・イベント一覧
 │    ├── 分析             : 4大分析ダッシュボード(食品別/曜日別/異常日比較/月間推移)
 │    ├── 食品管理画面     : 食品マスタ検索・閲覧・管理
 │    ├── イベント管理画面 : 全イベント履歴一覧・絞り込み・管理
 │    └── 設定             : 閾値設定、過去ログ再判定、開発モード切替
 │
 ├── ユーザーフォーム (UserForms)
 │    ├── frmAddMealEvent      : 食事イベント登録・編集（食品検索・明細自動計算）
 │    ├── frmAddEventData      : 活動イベント登録・編集
 │    ├── frmDailyEventManager : 日次イベント一覧・編集マネージャー
 │    ├── frmAddMealData       : 食品マスタ登録・編集（Gemini糖質推計支援）
 │    └── frmCategoryEdit      : 食品カテゴリ保守
 │
 └── 内部データシート (Hidden / Data Tables)
      ├── イベント記録 : 親テーブル（全イベントの親ヘッダ）
      ├── 食事明細     : 子テーブル（食品ごとの詳細行）
      ├── 食品マスタ   : 食品名・単位・基準糖質マスタ
      └── Libreデータ  : FreeStyleリブレ15分間隔生データ
```

### 2.1 シート一覧と機能仕様

| シート名 | 画面種別 | 主な機能・レイアウト仕様 |
| :--- | :--- | :--- |
| **`カレンダー`** | メイン画面 | ・**6週固定枠**（週数可変によるサイドバー崩れを防止、当月外はグレーアウト）。<br>・**土日色分け**（日曜日: 赤文字、土曜日: 青文字）。<br>・セル内に糖質合計(g)、インスリン量(単位)、異常アラートバッジ、活動アイコン（👟）を表示。<br>・日次血糖値推移スパークラインの埋め込み。<br>・右側**日次概要サイドバー**：選択日のサマリー数値、最新イベント情報、操作ボタン（「食事を記録」「活動を記録」「詳細を見る」）。 |
| **`日次詳細`** | 詳細画面 | ・選択された1日の詳細タイムライン表示。<br>・**24時間血糖値推移折れ線グラフ**（食前・食後血糖値マーカー、低血糖70/高血糖180の基準線、**凡例表示**）。<br>・食事・活動イベント一覧（固定表示枠＋上限超過時は「他○件あり [一覧・編集を開く ▶]」で管理フォーム起動）。<br>・カレンダーと統一されたカード調デザイン・水色基調の背景。 |
| **`分析`** | 分析画面 | ・**期間セレクタ**（当月 / 前月 / 直近30日 / 全期間）。<br>・**4大分析カード**：<br>　① 食品別血糖値インパクト分析（指定食品摂取前後の血糖変動・上昇幅）<br>　② 曜日別トレンド分析（月〜日ごとの平均血糖値＆低血糖/高血糖回数、重なり解消）<br>　③ 異常日と正常日の特性比較（糖質摂取量・インスリン投与量の差異）<br>　④ 月間推移トレンド（日次糖質量[g] vs インスリン量[単位]の推移）<br>・表示ラベルの最適化（「U」→「単位」、「糖質(g)」余分ラベルの整理）。<br>・*将来展望*: Gemini APIによる月間総合アドバイス・AIサマリー生成。 |
| **`食品管理画面`** | マスタ画面 | ・登録済み食品マスタの一覧・キーワード検索・カテゴリ絞り込み。<br>・新規食品登録・編集・カテゴリ管理ボタン。<br>・カレンダーサイドバーと統一されたデザインシステム。 |
| **`イベント管理画面`** | 一覧画面 | ・登録済みイベント（食事・活動・低血糖・高血糖）の全件一覧。<br>・日付・種別フィルター、選択行の編集・削除起動。 |
| **rmSettings** | 設定ダイアログ | ・各画面上部の「⚙ 設定」タブからポップアップ表示（画面遷移不要）。<br>・低血糖閾値（70 mg/dL）、高血糖閾値（180 mg/dL）、Gemini APIキー、モデル名の一括設定。<br>・**「保存して反映」ボタン**（1クリックで入力値保存、過去ログ自動再判定、カレンダー・分析画面の即時最新化を一気通貫で実行）。<br>・開発モード切替ボタン。 |

## 3. データモデル・テーブル設計

### 3.1 テーブル関連図 (ERD)

```
[ Libreデータ ] (生データ: 約8.4万件)
   │ 測定日時 (15分間隔), グルコース値 (mg/dL)
   │
   ▼ (自動判定バッチ: modAbnormalEvents)
[ イベント記録 ] (親テーブル) ──────────────────┐
   ├── イベントID (PK: yymmdd_hhnn / yymmdd_hhnn_L / _H) │
   ├── 日付 (Date), 時刻 (Time)                        │ 1:N
   ├── イベント種別 (食事 / 活動 / 低血糖 / 高血糖)      │
   ├── タイミング (朝食/昼食/夕食/間食)                  │
   ├── 糖質合計 (g), インスリン量 (単位)                │
   ├── 食前血糖値, 食後血糖値                           │
   └── メモ                                            │
                                                       ▼
                                                [ 食事明細 ] (子テーブル)
                                                   ├── 明細ID (PK: 連番)
                                                   ├── イベントID (FK)
                                                   ├── 食品名 (FK -> 食品マスタ)
                                                   ├── 食べた量, 単位
                                                   └── 糖質量 (g)

[ 食品マスタ ] ──────────────────────────────────────────┘
   ├── 食品名 (PK)
   ├── 基準量, 単位
   ├── 糖質量 (g)
   └── カテゴリ (主食, 主菜, 副菜, 菓子, 飲料 など)
```

### 3.2 テーブルカラム定義

#### ① イベント記録 (`wsEvent`)
| 列 | カラム名 | 型 | 説明・制約 |
| :---: | :--- | :--- | :--- |
| **A** | イベントID | String | 主キー。書式: `yymmdd_hhnn`（低血糖: `_L`、高血糖: `_H`、活動: `_A`） |
| **B** | 日付 | Date | 記録日（カレンダー・集計の主軸キー） |
| **C** | 時刻 | Time | 発生時刻（hh:mm:ss） |
| **D** | イベント種別 | String | `食事` / `活動` / `低血糖` / `高血糖`（**変更不可**） |
| **E** | タイミング | String | 朝食 / 昼食 / 夕食 / 間食（食事イベントのみ） |
| **F** | 糖質合計 | Double | 摂取糖質量合計(g)（食事明細から自動算出。活動時は空欄） |
| **G** | インスリン量 | Double | 投与量(単位)（活動時は空欄） |
| **H** | 食前血糖値 | Long | 食事開始前の直近リブレグルコース値 |
| **I** | 食後血糖値 | Long | 食後ピーク時のリブレグルコース値 |
| **J** | メモ | String | 補足メモ、活動内容、低血糖/高血糖の継続時間・最低/ピーク値 |

#### ② 食事明細 (`wsMeal`)
| 列 | カラム名 | 型 | 説明・制約 |
| :---: | :--- | :--- | :--- |
| **A** | 明細ID | Long | 主キー（一意の連番） |
| **B** | イベントID | String | 外部キー（`イベント記録.イベントID` と完全連動） |
| **C** | 食品名 | String | 食品マスタ参照食品名 |
| **D** | 食べた量 | Double | 摂取数量（例: 1.5, 200） |
| **E** | 単位 | String | 単位（杯, グラム, 個, 枚 など） |
| **F** | 糖質量 | Double | 当該明細の糖質量(g) = 基準糖質 × (食べた量 / 基準量) |

#### ③ 食品マスタ (`wsFood`)
| 列 | カラム名 | 型 | 説明・制約 |
| :---: | :--- | :--- | :--- |
| **A** | 食品名 | String | 主キー（重複不可） |
| **B** | 糖質量 | Double | 基準あたりの糖質量(g) |
| **C** | 値（基準量） | Double | 基準数量（例: 100, 1） |
| **D** | 単位 | String | 基準単位（g, 個, 杯 など） |
| **E** | カテゴリ | String | 主食 / 主菜 / 副菜 / デザート / 飲料 など |

## 4. データ整合性・セキュリティ規約（AGENTS.md完全準拠）

医療・健康情報を取り扱うシステムの信頼性を恒久的に保証するため、以下の5大原則を厳格に順守する。

1. **イベント種別の不変性（Immutability of Event Types）**:
   - 登録済みイベントの「種別（食事/活動/低血糖/高血糖）」は編集不可（UI上で変更不可）。
   - 種別を変更したい場合は「既存イベントを削除し、新規登録」を徹底し、孤立明細や不整合の発生を物理的に排除する。
2. **システム自動生成ログの不可侵性（Inviolability of System-Generated Records）**:
   - リブレ生データから閾値判定により自動抽出された「低血糖」「高血糖」イベントは客観的測定ログであるため、**手動での編集・削除を禁止（ロック）**とする。
   - 設定シートで閾値を変更した際は、再判定バッチにより冪等に再構築される。
3. **ユーザー手動管理対象の限定（User Operation Scope）**:
   - ユーザーが手動で登録・編集・削除できるのは「**食事**」と「**活動**」の2種のみとする。
   - 「活動」イベントには糖質・インスリン数値を持たせない（UI上でロック）。
4. **親子テーブル連動カスケード削除（Cascading Deletes）**:
   - 食事イベントを削除する際は、必ず `食事明細` シート内の同一 `イベントID` を持つ全明細行を連動削除し、孤立データを残さない。
5. **リアルタイム同期・ゼロクリア・自動保存保証**:
   - イベント登録・編集・削除完了時は、該当日のカレンダーセルおよびサイドバーを即時再計算する。
   - 該当日の数値が0になった場合は「0」ではなく完全な空欄（クリア）にする。
   - 登録・編集・削除確定後は、直ちに `ThisWorkbook.Save` を呼び出し、データの安全性を担保する。

## 5. UI/UX デザインシステム仕様

### 5.1 カラーパレット & タイポグラフィ
- **ベースカラー**: `#F4F7FC`（洗練されたオフホワイト／アイスブルー系背景）
- **プライマリカラー**: `#1E3A8A`（濃紺 / 見出し・主要アクセント）
- **セカンダリカラー**: `#3B82F6`（鮮やかなブルー / ボタン・アクティブ枠）
- **アラートカラー**:
  - 低血糖 (Hypo): `#EF4444`（鮮赤 / 70未満警告・日曜日表示）
  - 高血糖 (Hyper): `#F59E0B`（アンバーオレンジ / 180超警告）
  - 土曜日 (Sat): `#2563EB`（爽快なブルー表示）
- **タイポグラフィ**: `Meiryo UI` または `メイリオ`（全シート・全フォームで統一）

### 5.2 レイアウト & コンポーネントルール
- **カード調コンテナ**:
  各情報ブロック（カレンダー、サイドバー、分析グラフ、一覧表）は、白背景（`#FFFFFF`）＋薄いグレー境界線（`#E2E8F0`）のカード風スタイルで統一。
- **ボタンデザインの完全統一**:
  「食事を記録」「活動を記録」「詳細を見る」等の操作ボタンは、角丸半径・フォントサイズ（10pt太字）・余白・テキスト中央配置を共通化し、背景色のみで役割を区別する。
- **超過データの安全なUI誘導**:
  ワークシート上に膨大なデータを無理に並べず、定数行（5〜8件）の表示枠を設け、超過時はモーダル管理フォーム（`frmDailyEventManager`）をワンクリックで起動させる。

## 6. 主要モジュール構造とプロシージャ責務

| モジュール名 | 役割・責務 |
| :--- | :--- |
| **`modCalendar`** | カレンダーグリッド描画、月次データ集計、土日色分け、スパークライン生成、セル更新 |
| **`modDailyDetail`** | 日次詳細ダッシュボード更新、24時間血糖値グラフ描画（凡例付）、サイドメニュー描画 |
| **`modAnalysis`** | 4大分析処理（食品別・曜日別・異常日比較・月間推移）の集計・チャート描画、Gemini連携 |
| **`modAbnormalEvents`** | リブレデータ（15分間隔）からの低血糖・高血糖エピソード高速抽出・再判定バッチ |
| **`modSettings`** | 設定値（低血糖/高血糖閾値、期間、各種フラグ）の読み書き、開発モード切替 |
| **`modCommon`** | シート保護・解除、高速化設定（ScreenUpdating/Calculation制御）、日付・文字列共通関数 |
| **`modDatabase`** | イベント記録・食事明細のCRUD操作、カスケード削除、トランザクション保護 |

## 7. 開発・検証・学習方針

1. **コードの可読性と学習支援**:
   VBAの学習目的を支援するため、**すべてのモジュール・関数・プロシージャの冒頭に「概要」「引数」「戻り値」を明記した日本語解説コメント**を付与する。
2. **安全な実行環境（Safe Runner）**:
   COM自動化やマクロテスト時のExcelフリーズ・ゾンビプロセス発生を防止するため、タイムアウト監視付きランナー（`run_excel_safe.ps1` / `safe_excel_runner.py`）を経由してテストを実行する。
3. **プレゼンテーション・動画作成支援**:
   システムのアーキテクチャ・動作デモ・データ整合性設計の要点を、Canva用スライドおよびCapCut動画構成（テロップ・音声解説・画面キャプチャ）にスムーズに流用できる構成とする。
