# データ分析画面 詳細仕様書 (SPEC_ANALYSIS.md)

本ドキュメントは、血糖値・食事・インスリン統合管理システム Web版における **「データ分析画面（`src/components/analysis/AnalysisView.tsx`）」** の機能要件、UI設計、集計アルゴリズム（`src/lib/analysisCalculators.ts`, `src/lib/dateUtils.ts`, `src/lib/anomalyExtractor.ts`, `src/lib/realGlucoseLoader.ts`）、グラフ仕様、パフォーマンス最適化（日付インデックス＆オンメモリキャッシュ）、および医療安全・UX設計の受け入れ条件（DoD）を定めた仕様書（SSOT）です。
旧VBA資産（`legacy_vba/vba_exported/modAnalysis.txt`）の正解ロジックと1シート統合画面構造を100%継承・昇華して策定されています。

## 1. 画面概要 & 目的

データ分析画面は、日々蓄積されたリブレ血糖データ、食事内容、活動・インスリン投与データから、身体反応パターンや血糖変動の要因を分かりやすく可視化する画面です。
不要な説明文や重複する表示切替タブを引き算し、開いた瞬間に期間選択と4つの分析グラフ・集計表が一目で横断比較できる **「1画面統合ダッシュボード」** に一本化します。また、単一パス（`O(N + M)`）の日付インデックス集計とオンメモリキャッシュにより、期間切り替えやカテゴリ・食品切り替えを **待ち時間ゼロ（即時描画）** で実行します。

### 1.1 コア分析機能（旧VBA完全整合 4大分析）
1. **食品別 血糖上昇インパクト分析 (`src/components/analysis/FoodImpactTab.tsx`) [上段・左カラム配置]**:
   - **カテゴリ連動セレクトボックス**: 左側のセレクトボックスで食品カテゴリ（すべてのカテゴリ / 主食 / 主菜 / 副菜 / 間食・スイーツ 等、`categories` テーブルの `target_type = 'food'` に動的連動）を選択して食品候補を絞り込み、右側のセレクトボックスから対象食品（例: 「ごはん」「うどん」「カレーライス」等）を素早く選択する。
   - **4大サマリー＆食事履歴全件表示**: 選択した食品の **「食べた回数」「平均インスリン」「食前→ピーク平均」「平均上昇幅（Δ血糖値）」**、および **「一緒に食べたもの（行クリックで開閉）」** を全件一覧・相関分析する。
   - **モバイル（スマートフォン）横スクロール完全ゼロ設計 ＆ 高視認性アコーディオン**:
     - 左端の「日時」列は1行目に「日付＋1文字区分バッジ（`朝` / `昼` / `夕` / `間`、例: `8/25 [夕]`）」、2行目に「時刻（例: `19:15`）」を改行表示して列幅を最小化する。
     - 2列目の見出しを「**量・糖質**」に短縮し、1行目に「食べた量＋糖質量（例: `1杯 (55.2g)`）」、2行目に「`＋他3品 ▾`」バッジを配置することで、スマートフォン（幅360px〜）でも横スクロールを発生させずに全5列（`日時` / `量・糖質` / `インスリン` / `食前→ピーク` / `Δ上昇幅`）を1画面幅内に完全収容する。
     - 行タップで展開する「**一緒に食べたもの**」アコーディオンは、上段に品数と「食事合計糖質バッジ」を配置し、下段に各食品を個別のピル（タグ）カード（例: `[ハンバーグ 12.5g]` `[野菜サラダ 3.5g]` `[コーンスープ 12.5g]`）として並べることで、食品名の途中改行を防ぎ一目で読み取れるデザインとする。
   - 隣の「曜日別 傾向分析」エリアとコンテンツの高さを揃え、整然とした2カラム比較を実現する。
2. **曜日別 傾向分析 (`src/components/analysis/WeekdayTrendsTab.tsx`) [上段・右カラム配置]**:
   - 日曜日〜土曜日の7曜日ごとに「1日平均糖質摂取量(g)」「平均血糖値(mg/dL)」「異常値件数」を集計し、グラフと7曜日集計内訳表を常時表示して平日と休日の生活リズムの乱れを浮き彫りにする。
   - **医療安全（低血糖防止）および視認性設計**: 曜日別の「平均インスリン量」は糖質量（200〜300g）に対して数値変動が小さくグラフ上で潰れるだけでなく、「特定の曜日の血糖値が高いのは平均インスリン量が少ないから増量すればよい」という危険な自己判断（低血糖リスク）を招く恐れがあるため、曜日別グラフ・一覧からは除外し、**「糖質摂取量と平均血糖値の相関」** に集中させる。
3. **時間帯別 異常値パターン分析 (`src/components/analysis/TimeAnomalyTab.tsx`) [中段・2カラム幅（左：集計表 ／ 右：横棒グラフ）]**:
   - 朝（06:00〜11:59）、昼（12:00〜17:59）、夕・夜（18:00〜23:59）、夜間・未明（00:00〜05:59）の4区分ごとの低血糖・高血糖発生件数、割合、および発生傾向を、設定画面の目標基準値（`hypoThreshold` / `hyperThreshold`）に連動して可視化する。
   - 旧VBAプロジェクトの画面配置に準拠し、**左側に4時間帯の集計内訳テーブル、右側に横棒グラフ（Horizontal Bar Chart）** を並べて配置する。
4. **指定期間の糖質摂取量 & インスリン量 推移グラフ (`src/components/analysis/CarbInsulinTrendTab.tsx`) [下段・2カラム幅フルワイド]**:
   - **期間プリセット（直近7日・14日・30日・90日・全期間）＋ 月別セレクトボックス（`YYYY年M月`）**:
     - 「直近30日」と期間が重複していた「最新月」ボタンを廃止し、代わりに実データが存在するすべての年月（例: `2026年8月`、`2026年7月`、`2026年6月`...）を月単位で自由に切り替えられる **月別セレクトボックス** を設ける。
   - 日次の糖質摂取量（g: 棒グラフ）と総インスリン投与量（U: 折れ線グラフ、食事インスリン＋活動・持効型インスリン合算）のバランスを複合時系列で可視化し、集計期間が広い場合でもグラフが潰れないよう **2カラム分のフル幅** で描画する。
   - 期間の基準日はデータベース内の最新記録日（`referenceDateStr`）に自動アンカーされ、「全期間（`all`）」選択時はデータベース内の **最古記録日（`earliestDateStr`）〜最新記録日（`referenceDateStr`）** の実データ存在期間を正確に集計対象とする。

## 3. 各分析機能の詳細仕様 & 臨床算出アルゴリズム (`src/lib/analysisCalculators.ts`)

### 3.1 タイムゾーン安全な日時・時刻・曜日抽出 (`src/lib/dateUtils.ts`)
- すべてのイベント日時および測定タイムスタンプの時刻（`0〜23`時）、日付（`YYYY-MM-DD`）、曜日（`0〜6`）、およびミリ秒差分は、`new Date(iso).getHours()` や `toISOString()` によるタイムゾーンズレ（±9時間）を排除するため、必ず `src/lib/dateUtils.ts` の `extractHour`、`extractDateStr`、`extractTimeStr`、`getDayOfWeekFromDateStr`、`parseWallClockMs`、`formatLocalDate` を使用する。

### 3.2 複合インデックスによる期間局所取得 & オンメモリキャッシュ設計 (`src/lib/analysisCalculators.ts`, `src/lib/echartsCore.ts`)
- **全件取得（`toArray`）の排除と複合インデックス `between()` による期間ピンポイント取得**:
  - 初回表示時は `[user_id+timestamp]` および `[user_id+event_datetime]` の先頭・末尾レコード（`.first()` / `.last()`）のみから `earliestDateStr`（最古記録日）と `referenceDateStr`（最新記録日）の境界メタデータ（`AnalysisBoundaryMetadata`）を高速特定する。また、`src/lib/realGlucoseLoader.ts` の Phase 2 バックグラウンド過去データ同期完了イベント（`cgm-background-hydration-complete`）を受信した際は、最古記録日（`2024-09-16`）および月別セレクトボックス候補（`availableMonths`）を自動更新する。
  - 選択された期間（`7d`, `14d`, `30d`, `90d`, `month:YYYY-MM`, `all`）に対し、`db.libre_readings.where('[user_id+timestamp]').between(...)`（食前・食後探索用の前後1日余白含む）、`db.events.where('[user_id+event_datetime]').between(...)`、および `db.meal_details.where('event_id').anyOf(mealEventIds)` で必要期間のデータのみを局所取得し、`PrecomputedPeriodSlice` としてメモリキャッシュ（`periodSlices` Map）に保持する。一度表示した期間は再計算・再クエリなしで0msで即時再利用する。
- **全期間（`all`）・月別（`month:YYYY-MM`）および期間スライスの正確な境界決定**:
  - 「全期間（`all`）」選択時は、固定の過去日（2020年等）ではなく `earliestDateStr` から `referenceDateStr` までの実データ記録期間を対象とする。
  - 「月別セレクトボックス（`month:YYYY-MM`）」選択時は、指定された年月の初日（`YYYY-MM-01`）から末日までを集計対象とし、データセットの `earliestDateStr`〜`referenceDateStr` の範囲にクランプすることで、月途中の最新月や最古月でも正確な対象日数・平均値を算出する。

### 3.3 機能 1: 食品別 血糖上昇インパクト分析 (旧VBA `AnalyzeSelectedFood`)
- **カテゴリ連動による食品選択**:
   - カテゴリセレクトボックス（`すべてのカテゴリ` または登録済み食品カテゴリ）を選択すると、該当カテゴリに属する食品のみに対象食品セレクトボックスの選択肢を絞り込む。カテゴリ変更時に現在の選択食品が絞り込み後の候補に含まれない場合は、候補先頭の食品を自動選択して即座に分析結果を更新する。
- **スマートフォンでも横スクロール・文字崩れゼロの5列構成テーブル**:
   - **日時列の2段改行＆1文字区分バッジ**: 1行目に日付（`MM/DD` 形式）と1文字に短縮した食事区分バッジ（`朝` / `昼` / `夕` / `間`）、2行目に時刻（`HH:mm`）を改行して表示し、左端列の横幅を最小化する。
   - **「量・糖質」列への短縮と2段構成**: 見出しを `量・糖質` に短縮し、1行目に「食べた量＋糖質量（`1杯 (55.2g)`）」、2行目に「`＋他3品 ▾`」ボタンを配置する。
   - **品目別ピル（タグ）型アコーディオン**: 行タップで展開する「一緒に食べたもの」内訳では、上段に品数と「食事合計糖質バッジ」を左右に分けて表示し、下段に各品目を白背景の独立したピル型バッジ（食品名＋糖質量バッジ、折り返し禁止 `whitespace-nowrap`）として並べることで、長い食品名が途中で分断されるのを防ぎ視認性を高める。

### 3.4 機能 2: 曜日別 傾向分析 (旧VBA `AnalyzeWeekdayTrends` + 医療安全改善)
- **画面表示項目（グラフ＆常時表示テーブル）**:
   - `1日平均糖質 (g)`: 該当曜日の1日あたり平均糖質摂取量（左Y軸・棒グラフ、目盛りラベル `{value}g`）
   - `平均血糖値 (mg/dL)`: 該当曜日の全グルコース測定値の算術平均（右Y軸・折れ線グラフ、目盛りラベル `{value}`）
   - `異常値件数 (件)`: 該当曜日に発生した低血糖・高血糖イベントの合算件数
   - デスクトップ（`1280x800`）表示時に「曜日別 集計内訳」テーブルの最初のデータ行までがファーストビュー内に収まり、かつスマートフォン（`375x812`）表示時にも内部テーブルが横スクロールなしで全5列収まるよう、セル余白（`px-1.5 sm:px-3`）とモバイル時のヘッダー装飾アイコン非表示を適用する。

### 3.5 機能 3: 時間帯別 異常値パターン分析 (旧VBA `AnalyzePeriodTrends`)
- **左右2カラム構成（左：4時間帯集計表 ／ 右：横棒グラフ）**:
   - 朝（06:00〜11:59）、昼（12:00〜17:59）、夕・夜（18:00〜23:59）、夜間・未明（00:00〜05:59）の4区分について、左側に常時表示の集計テーブル、右側にY軸を時間帯・X軸を件数とした横棒グラフ（Horizontal Bar Chart）を描画する。
   - スマートフォン（`375x812`）でも4時間帯集計テーブルの全5列（時間帯・低血糖・高血糖・合計・割合）が横スクロールなしで一望できるよう、時間帯名と時刻範囲をモバイルでは2段表示にしてセル余白（`px-1.5 sm:px-2.5`）を最適化する。

### 3.6 機能 4: 糖質・インスリン 推移グラフ (Apache ECharts フルワイド)
- **2カラム分のフル幅描画 & 全チャート即時レンダリング**:
   - 長期間（90日・全期間等）を選択した際にも日次推移が見やすいよう、2カラム分の横幅全体を使って描画する。
   - `WeekdayTrendsTab.tsx`・`TimeAnomalyTab.tsx`・`CarbInsulinTrendTab.tsx` の全EChartsグラフに `animation: false` を設定し、アニメーション途中の棒グラフ・折れ線欠けを防止して画面表示と同時に100%完成したチャートを描画する。
   - `AnalysisView.tsx` マウント時にオンメモリキャッシュ（`boundaryMeta.periodSlices`）から初期期間スライス（`30d`）を同期初期化し、データ検索前に `pauseBackgroundHydration` を呼び出すとともに、`setPeriodSlice` の関数型アップデータ内での副作用（`setIsLoading(true)` のレンダリング中呼び出し）を排除してオンメモリDB（同一マイクロタスク解決）でも競合なく即座に描画が完了するようにする。
