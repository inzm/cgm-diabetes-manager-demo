# カレンダー画面 & 日次詳細ドロワー 詳細仕様書 (SPEC_CALENDAR.md)

本ドキュメントは、血糖値・食事・インスリン統合管理システム Web版における **「共通ヘッダー・ナビゲーション」「カレンダー画面（トップページ）」および「日次詳細ドロワー（ボトムシート/サイドパネル）」** の機能要件、UI設計、データモデル、ジェスチャー操作、および受け入れ条件（DoD）を定めた仕様書（SSOT）です。

---

## 1. 画面概要 & 設計思想

カレンダー画面は、患者および見守り家族が月間を通じた血糖コントロール状態、食事・インスリン、および血糖アラートを直感的に俯瞰・操作するためのメイン画面（トップページ）です。

### 1.1 コアUX原則
1. **ファーストビューでカレンダー全体を俯瞰可能（PC・スマホ共通）**:
   - 上部の「選択日サマリー」を極限までコンパクトに設計し、月間全体統計や冗長な見出しラベルを排除することで、PCでもスマホでも開いた瞬間にカレンダーグリッド全体が一目で把握できるようにする。
2. **タップで即座に日次サマリー更新 & 再タップで日次詳細ドロワー展開**:
   - 未選択の日付セルをタップすると、上部の「選択日サマリー」が即座に切り替わる。
   - 選択中の日付セルをもう一度タップ（またはサマリーバーをタップ）すると、スマホでは「ボトムシート」、PCでは「右側スライドパネル」として日次詳細ドロワーが展開される（※日次詳細の専用ページは設けず、すべてこのドロワーに集約する）。
3. **直感的なカラールール（曜日 & 異常値）と設定基準値の完全連動**:
   - **曜日・日付色**: 日曜始まり（日〜土）とし、**日曜日の日付は赤系（`text-rose-600`）**、**土曜日の日付は青系（`text-blue-600`）** で表示。
   - **異常値カラー**: 直感的な理解のため、全画面を通じて **低血糖（`▼`）＝ 青系（`text-blue-600`）**、**高血糖（`▲`）＝ 赤系（`text-rose-600`）** に統一する。
   - **設定閾値との動的連動**: 平均血糖値の色分け、セル内スパークラインの正常目標帯、および凡例テキストはすべて設定画面の目標範囲（`hypoThreshold` / `hyperThreshold`）と動的に連動する。
4. **セル内の5行レイアウトとスパークラインのアスペクト比最適化**:
   - カレンダーセル内で文字が隠れたり重なったりしないよう、5行構成（1行目: 日付＋異常値ラベル、2行目: 糖質量、3行目: インスリン量、4行目: 平均血糖値、5行目: 24Hスパークライン波形）で配置する。
5. **PCサブナビとモバイルボトムナビの完全統一 & ユーザー目線名称**:
   - メイン画面タブは PC・スマホともに **`カレンダー` / `食品・活動` / `分析` / `設定`** に統一（モバイルボトムナビ中央にはスピードダイヤル式の `＋記録` ボタンを配置、PCサブナビ右端には `CSV取込` ボタンのみを配置）。

## 3. UIコンポーネント詳細仕様

### 3.1 専用ログイン画面（Auth Gate）・ヘッダー & ナビゲーション (`src/components/common/AuthGateScreen.tsx`, `src/components/common/Header.tsx`, `src/components/common/BottomNav.tsx`, `src/App.tsx`)
- **本番モードにおける未ログイン時の専用ログイン画面（Auth Gate）強制ロック (`src/components/common/AuthGateScreen.tsx`, `src/App.tsx`)**:
  - 本番環境（`VITE_APP_MODE=personal` かつ Supabase 接続有効時、`isAuthRequired === true`）では、未ログイン状態（`!authUser`）またはアクセス権限未承認時（`!isAccessAuthorized`）にヘッダー・カレンダー画面・分析画面・ナビゲーション等を一切描画せず、フルスクリーンの「専用ログイン画面（`src/components/common/AuthGateScreen.tsx`）」のみを表示して第三者の閲覧・操作を100%遮断する。
  - ログイン画面には「ログイン」と「招待されたご家族の新規登録」の切替タブ、および折りたたみ式の「はじめてご利用になる方・招待されたご家族の手順」ガイドを配置する（詳細は [`USER_GUIDE.md`](USER_GUIDE.md) および [`SPEC_SETTINGS.md`](SPEC_SETTINGS.md) を参照）。
  - 公開デモモード（`VITE_APP_MODE=portfolio`）およびローカルE2Eテスト環境では Auth Gate を表示せず、即座にカレンダー画面を描画する。
- **ヘッダー (`src/components/common/Header.tsx`)**:
  - 清潔感のある白基調（`bg-white/95 backdrop-blur-md border-b border-slate-200/90`）のモダンな医療アプリヘッダーとし、二重枠線を排してCGM水滴＆波形アイコン（`public/icons/icon-192.svg`）自体の鮮やかなグラデーションが映えるデザインとする。
  - **左右の視覚バランス設計 & 未来月への遷移制限**:
    - 左側: アプリアイコン（`public/icons/icon-192.svg`）＋ブランドタイトル「リブレ・食事管理」を配置。
    - 右側: カレンダー表示時は `◀ YYYY年 M月 ▶` ＋ 独立した **`[今月]` ボタン**（現在の日付の月への移動）＋ 独立した **`[↻]` ボタン**（カレンダーデータの再読み込み更新）を配置。他画面表示時は、中央に中途半端にテキストが浮くのを防ぐため、右側にアイコン付きの現在画面ピルバッジ（`よく使う食品・活動` / `データ分析` / `設定`）およびオフライン・閲覧専用バッジを整然と右寄せ配置する。
    - **現在の日付の月までの表示・未来月の遷移制限**: データ取込にはCSVダウンロードが必要なため常に最新データが取得されているとは限らないことから、デモアプリ・通常モードを問わずカレンダーは**「現在の日付の月（`new Date()` の年月）」まで表示・移動可能**とし、それより未来の月は表示・遷移しない（初期表示は最新データが存在する `2026年 8月` を表示し、`[今月]` ボタンや `▶` ボタンで現在の日付の月まで移動可能とする）。カレンダーが現在の日付の月（上限月）を表示している時は、ヘッダーの「翌月（`▶`）」ボタンを `disabled`（非活性・視覚的にも薄く表示）にする。
- **ナビゲーションタブ & 片手操作向け左右スワイプ画面遷移**:
  - PC用サブナビ・モバイル用ボトムナビともに以下の構成（並び順：`calendar` ⇔ `events` ⇔ `analysis` ⇔ `settings`）に統一：
    - `calendar`: カレンダー
    - `events`: 食品・活動（よく使う食品・活動・カテゴリの追加/編集/削除）
    - `analysis`: 分析
    - `settings`: 設定
  - モバイル用ボトムナビ（`BottomNav.tsx`）は親指でのタップおよび下部バースワイプ操作が行いやすいゆとりある高さ（`h-[4.5rem]` / 72px ＋ `env(safe-area-inset-bottom)`）とし、中央には `＋記録` ボタン（食事記録 / 活動記録 / CSV取込のスピードダイヤル）を配置。
  - PC用サブナビ右端には `CSV取込` ボタンのみを配置し、冗長な食事記録・活動記録ボタンは置かない。
  - **デモアプリ（ポートフォリオモード）におけるCSV取込ボタンの非活性化**: デモアプリ（`isPortfolioMode()`）では、PCサブナビおよびモバイルボトムナビのスピードダイヤル内のCSV取込ボタンを `disabled`（非活性化）にし、**「デモアプリでは利用できません」** というメッセージをボタン上に明示する。
  - **非カレンダー3画面（`食品・活動` / `分析` / `設定`）でのコンテンツ左右スワイプによるタブ切り替え**:
    - スマホ片手操作（右手親指等）で遠くの下部メニューボタンをタップせず直感的に画面移動できるよう、非カレンダー3画面のコンテンツ領域で左右スワイプ（`Math.abs(deltaX) > Math.abs(deltaY) * 1.2` かつ `Math.abs(deltaX) > 50`）した際、下部メニューの並び順に従って前後のタブへ遷移する（左スワイプ `deltaX < -50` で右隣のタブへ進み、右スワイプ `deltaX > 50` で左隣のタブへ戻る。左端 `calendar`・右端 `settings` でストップ）。
    - 誤発火防止ガード：横スクロール可能な要素（`.overflow-x-auto` 等）やフォーム入力要素（`input` / `select` / `textarea`）上でのタッチ操作、およびモーダル・ダイアログ開表示中はタブスワイプを発火させない。
  - **下部メニューバー（`BottomNav.tsx`）上の左右スワイプによるタブ切り替え**:
    - カレンダー画面で過去の月を閲覧している時でも1回のスワイプで隣のタブへ移動できるよう、下部ナビゲーションバー（`BottomNav`）領域上での左右スワイプ（`Math.abs(deltaX) > Math.abs(deltaY) * 1.2` かつ `Math.abs(deltaX) > 50`）でも下部メニュー順にタブを切り替えられるようにする。
  - **画面タブ切り替え時の方向連動マイクロ・スライド＆フェードアニメーション (`src/index.css`, `src/App.tsx`)**:
    - `NAV_TAB_ORDER`（`['calendar', 'events', 'analysis', 'settings']`）における遷移前後のインデックス差から移動方向（右側のタブへ進む＝`'forward'`、左側のタブへ戻る＝`'backward'`）を判定し、タブ切り替え時（PCサブナビ・モバイルボトムナビ・コンテンツ左右スワイプ・下部バースワイプすべて）に **180ms（`cubic-bezier(0.16, 1, 0.3, 1)`、移動幅 `14px`）の軽量GPU合成マイクロ・スライド＆フェードアニメーション**（`.cgm-slide-fade-forward`: 右から左へスライドイン / `.cgm-slide-fade-backward`: 左から右へスライドイン）を適用する。
    - アニメーション完了時（`100%`）には必ず `transform: none` に戻し、子孫要素の `sticky` / `fixed` 配置や ECharts の幅計算に一切悪影響を与えない構造とする。また、コンテナに `overflow-x: clip` を適用して遷移中の横スクロールバー発生を防止し、`@media (prefers-reduced-motion: reduce)` 環境ではアニメーションを無効化する。
  - **デモ環境案内モーダル（初期化完了の目印） (`src/components/common/DemoWelcomeModal.tsx`, `src/App.tsx`)**:
    - デモアプリ（`isDemoCsvImportDisabled() === true`）を開いたとき、ページを再読み込み（リロード）したとき、およびブラウザのbfcache（`pageshow` の `event.persisted === true`）から復帰したときに**毎回**、カレンダーのファーストビューが後ろに透けて見えるコンパクトなモーダル（タイトル：`デモ環境について`）を自動表示する。
    - `sessionStorage` 等による同タブリロード時の非表示制御を行わず、ページを開くたび・再読み込みするたびに毎回表示されることで、データが初期状態にリセットされたことをユーザーが直感的に理解できる目印として機能させる。
    - モーダル内は3段カードや装飾アイコン、「マスタ」、「のストレージ」、（）書きを排し、自然な3段落の文章（第1段落：「本アプリは、血糖測定器のデータと日々の食事・活動・インスリンの記録をまとめて管理し、カレンダーやグラフで血糖値の変動を振り返るためのWebアプリです。」、第2段落：「血糖値や食事・活動の履歴データは予め組み込んであり、食事や活動の記録、よく使う食品・活動は自由に追加や削除、編集を行うことができます。」、第3段落：「このデモアプリで登録・変更した内容は、お使いのスマートフォンやPCには保存されません。ページを再読み込みするかタブを閉じると、登録・変更した内容は破棄され、初期状態に戻ります。」）のみを簡潔に表示する。
    - 下部の **`閉じる`** ボタン（`data-testid="btn-start-demo"`）、右上の **`[✕]`** ボタン、背景オーバーレイのタップ、または `Escape` キーのいずれでも即座に閉じることができ、オープン時には閉じるボタンへの初期フォーカス付与・`Tab` / `Shift+Tab` フォーカストラップ、および背後のカレンダースワイプやタブスワイプが誤発火しないようガードする。

### 3.2 選択日コンパクトサマリー (`src/components/calendar/SelectedDaySummary.tsx`)
- **ヘッダー直下への固定配置（Sticky追従）**:
  - カレンダーを縦スクロールした際も選択日サマリーバーが隠れないよう、`sticky top-12 z-30`（ヘッダー直下への固定配置＋半透明ブラー背景）を適用し、下週の日付セルをタップした際も常に上部にサマリーが視認できる状態を維持する。
- **選択日付・曜日の視認性強化（ピルバッジ強調）と不要要素の排除 & 凡例ポップオーバー連動**:
  - 月間全体統計、および「選択中の日付サマリー」「タップで詳細展開」「詳細を見る ➜」「指標」「詳細 ➜」、カード右上の小ラベル、下部の補足テキストは一切表示しない。
  - **PC表示時（`hidden sm:flex`）の選択日付・曜日バッジ強調**:
    - 選択日付（例: **`8月25日 (火)`**）を **`text-lg font-black` の強調ピルバッジ**（日曜=ローズ系背景/枠、土曜=ブルー系背景/枠、平日=スレート系背景/枠）として左端に配置し、現在どの日付・曜日のサマリーを見ているかが即座に判別できるようにする。
  - **スマホ表示時（`sm:hidden`）の日付・曜日ピルバッジ強調と省スペース1行設計 & 凡例アイコンボタン**:
    - スマホ表示時にも必ず曜日を含めて **`8/25 (火)`**（`M/D (曜)` 形式）と表示し、日付と曜日がひと目で目立つピルバッジデザイン（**`text-sm font-black`**、日曜=ローズ系背景/枠、土曜=ブルー系背景/枠、平日=スレート系背景/枠）で左端に強調配置する。
    - 「血糖」「糖質」の文字ラベルを廃止し、アイコン＋数値＋単位（`🩸148mg` ｜ `🍚171.8g` ｜ `💉43U` ｜ `▼0 ▲1`）のみで1行にゆとりを持って収める。
    - 右端に独立した**凡例アイコンボタン（`!` / `AlertCircle` アイコン）**を配置し、タップ時に吹き出し（ポップオーバー）でカレンダー記号の凡例（`▲ 高血糖アラート(>${hyperThreshold})` / `▼ 低血糖アラート(<${hypoThreshold})` / `🍚 糖質` / `💉 インスリン` / `🩸 平均血糖値`）およびスマホのジェスチャー操作ヒントを表示する。これによりカレンダー下部の凡例領域をスマホ時は非表示（`hidden sm:flex`）にし、縦スクロール競合を防止する。
- **表示項目（PC・スマホ共通）**:
  - **選択日付・曜日バッジ**: PC時は **`8月25日 (火)`**（`text-lg font-black`）、スマホ時は **`8/25 (火)`**（`M/D (曜)` 形式、`text-sm font-black`）。ともに曜日カラー（日曜=ローズ系背景/枠、土曜=ブルー系背景/枠、平日=スレート系背景/枠）のピルバッジで強調表示する。

  - **インスリン量**: `43 U`（食事インスリン＋単体・持効型インスリンの日次総和）

### 3.3 カレンダーセル (`src/components/calendar/CalendarDayCell.tsx`) & スパークライン (`src/components/calendar/Sparkline.tsx`) & カレンダーグリッド (`src/components/calendar/CalendarGrid.tsx`)
スマホ画面でも絵文字やスパークラインを省略せず、文字切れ・重なりを起こさずに全指標を視認できるよう、縦方向の余白を活用した **5行構成** とし、「日付数字」が最も明瞭に判別できるよう異常値ラベル・平均血糖値との視覚的階層（コントラスト）を最適化する：
- **設定閾値（`hypoThreshold` / `hyperThreshold`）との完全連動**:

  - **左右スワイプ（`Math.abs(deltaX) > Math.abs(deltaY) * 1.2` かつ `Math.abs(deltaX) > 50`）**:
    - 右方向スワイプ（`deltaX > 50`）：前月（過去の月）へ移動する。
    - 左方向スワイプ（`deltaX < -50`）：過去の月を表示している場合は翌月へ移動し、**すでに最新月（上限月）を表示している場合は未来の月へ移動せず、右隣のタブである「食品・活動（`events`）」画面へ遷移する**。

## 4. 環境別データ取得・本番データ保護・デモ用リアル血糖値データ基盤 (`src/lib/aggregates.ts`, `src/lib/anomalyExtractor.ts`, `src/lib/dateUtils.ts`, `src/lib/realGlucoseLoader.ts`, `src/lib/uuidUtils.ts`, `src/components/calendar/CalendarView.tsx`)

- **ポートフォリオモード (`VITE_APP_MODE=portfolio`) におけるリアル血糖値・実測連動食事データ基盤・2フェーズ高速段階的同期 (`src/lib/realGlucoseLoader.ts`, `public/data/real_glucose_recent.json`, `public/data/real_glucose_readings.json`)**:
  - 合成されたデモデータ（サイン波血糖値や不自然なランダム食事記録）は一切生成せず、ポートフォリオモードでのみ実測CGMデータを2フェーズで段階ロードする。生成される測定値・異常値・食事・活動・明細のIDはすべて `src/lib/uuidUtils.ts` の `deterministicUuid` による正規UUIDとする。
  - **Memory-First 2フェーズ段階的同期（Memory-First Lazy Sync）による初期描画 0.3秒化**:
    - **Phase 1（Memory-First 即時初期描画）**: `portfolio` ビルド時に注入される `<link rel="preload">` およびモジュール初期化時の先行プリフェッチにより直近期間データ（`public/data/real_glucose_recent.json`：3,482件、約91KB / gzip 18KB）をJSバンドルと並列取得し、メモリ上（`inMemoryRecentCache`）で即座に展開する。IndexedDB の重いトランザクション完了を待たずに `CalendarView.tsx` および `DailyDetailDrawer.tsx` へメモリから直接データを提供（初期データ準備完了時に User Timing API マーク `cgm-calendar-data-ready` を記録）するため、初回アクセス・リロードともに **0.3〜0.5秒以内** でカレンダーが即座に描画される。
    - **Phase 1.5 & Phase 2（バックグラウンド非ブロッキング永続化＆過去データ同期）**: カレンダー初期描画完了後に、裏側で直近データの永続化・初期食品シード（`seedFoodMasterIfEmpty`）を実行し、続いて全期間データ（`public/data/real_glucose_readings.json`：79,479件、2024年9月〜2026年8月）を取得して小チャンク（6,000件単位＋40ms休止）で順次格納する。完了時に `cgm-background-hydration-complete` イベントで最新データ月（`latestDataDate` から動的導出）以外の過去月キャッシュ・分析期間境界を自動更新する。
    - なお、設定画面で「記録データを初期化」が実行された場合（`markPatientManuallyCleared`）は、同一セッション内でカレンダーや分析画面へ遷移してもデモデータが勝手に再ハイドレーションされないよう抑止し、`resetDemoDataToInitialState` 実行時のみ抑止フラグを解除する。
  - ポートフォリオ環境（`VITE_APP_MODE=portfolio` かつ `window.__CGM_E2E_ALLOW_CSV_IMPORT__ !== true`）では、採用担当者や閲覧者のスマートフォン端末の物理ストレージを一切圧迫しないよう、`src/lib/db.ts` の全テーブルをオンメモリストア（`InMemoryTable`）として動作させ、物理 IndexedDB（`cgm_diabetes_manager_db`）への永続書き込みを行わないとともに、起動時・`pagehide` 時・手動リセット時に既存の物理 IndexedDB を自動削除（パージ）する。これにより、閲覧者が食事記録・食品登録・活動登録・カテゴリ編集・削除をすべて試せる一方、ページ再読み込み時または設定画面の「デモデータを初期状態に戻す」実行時には初期シード状態へ100%クリーンにリセットされる。
  - ポートフォリオモードでは初回表示時に最新の実測データ月（2026年8月）を最初から表示することで、余分な月ジャンプ再レンダリングなしで開いた瞬間にリアルな血糖波形と食事・異常値エピソードを確認できるようにする。
  - 表示中の年月に記録が1件もなく、他の年月に実データが存在する場合は、カレンダー上部に「最新の記録がある YYYY年M月 を表示」ボタンを表示し、ワンクリックで移動できるようにする。

  - 日次詳細ドロワー（`DailyDetailDrawer.tsx`）でのイベント削除時も `triggerBackgroundCloudSync` を実行し、24時間血糖チャート（`DailyGlucoseChart.tsx`, `src/lib/echartsCore.ts`）は `React.lazy()` で初回オープン時に遅延ロードする。
- **デスクトップ1画面（`1280x800`）完結レイアウト・空セルノイズ排除・24Hチャート即時描画**:
  - デスクトップ表示時（`1280x800`）において、6週分のカレンダーセル（`sm:min-h-[88px] lg:min-h-[92px]`）と下部の凡例バー（`【凡例】`）が縦スクロールによる見切れなしに1画面内へ収まるよう余白を最適化する。
  - 記録が1件もない空の日付セルでは `--` プレースホルダーの3段重ね表示を行わず、余白を活かしたクリーンなセル表示とする。モバイル選択日サマリーバーの平均血糖単位は医学的に正確な `mg/dL` と表記する。
  - 日次詳細ドロワーの24時間血糖チャート（`DailyGlucoseChart.tsx`）では `animation: false` を設定し、血糖曲線・垂直ドロップ破線・底部イベントマーカー（`●`/`◆`/`▲`/`▼`）がアニメーション遅延なく同時に100%描画されるようにする。また、ECharts `tooltip.formatter` 内で描画される動的文字列（`d.memo`, `d.category`, `d.timeLabel` 等）はすべて `escapeHtml`（`src/lib/utils.ts`）でサニタイズし、DOM-based XSS を100%防止する。さらに、デモアプリ（`isDemoCsvImportDisabled()`）において血糖データのない日付を選択した際は、CSV取込の案内ではなく「記録のある日付（2026年8月以前）を選択すると24時間推移が表示されます」と整合した案内を表示する。

## 5. 受け入れ基準 (Definition of Done: DoD)

- [x] **DoD-1: コンパクトな選択日サマリー表示 & スクロール固定（PC・スマホ共通）**
  - 月間統計や不要ラベルを排し、PC・スマホともに「平均血糖値」「糖質量」「インスリン量」「異常値回数（▼低=青 / ▲高=赤）」がヘッダー直下に固定（Sticky）表示され、カレンダーをスクロールしても常時視認できること。
- [x] **DoD-2: カレンダーセルの5行階層配置・日曜赤/土曜青・スパークライン視認性・設定閾値完全連動**
  - 日曜が赤、土曜が青で表示され、異常値が `▼`(青)・`▲`(赤) でコンパクトに表示され、平均血糖値色分け・スパークライン目標帯・凡例テキストがすべて設定閾値（`hypoThreshold` / `hyperThreshold`）と連動すること。
- [x] **DoD-3: カレンダー・サマリー・日次ドロワー・分析画面間の数値100%一致 & 食前・食後血糖表示**
  - 異常値回数、インスリン合計（食事＋持効型等の単体投与）、糖質合計、および設定閾値が全画面で完全一致し、日次ドロワーの食事カードに食前→食後ピーク血糖値（上昇幅 Δ）が表示されること。
- [x] **DoD-4: 本番モードでのデモデータ完全遮断・ポートフォリオモードでのリアル血糖値データ（79,479件）描画 & 24H垂直ドロップ破線・XSS防御**
  - 本番モード（`VITE_APP_MODE=personal`）ではデモデータが一切自動投入されず今日・当月が表示され、ポートフォリオモード（`VITE_APP_MODE=portfolio`）では実測血糖値データ（`public/data/real_glucose_readings.json`）が使用されること。また、24Hグラフに食事・活動（実施時間）・高血糖・低血糖の垂直ドロップ破線が描画され、ツールチップ内の動的文字列がHTMLエスケープされていること。
- [x] **DoD-5: 家族閲覧ロールの認可制御・デモアプリCSV取込非活性化 & 品質ゲート通過**
  - `isReadOnly === true` 時に追加・編集・削除がロックされ、デモアプリ（`isPortfolioMode()`）ではPCサブナビ・モバイルスピードダイヤルのCSV取込ボタンが `disabled` かつ「デモアプリでは利用できません」と表示され、`npm run verify:all` および `npm run test:smoke` がエラーゼロでパスすること。
- [x] **DoD-6: 現在の日付の月までの表示・未来月への遷移制限・ドロワー下スワイプ時のリロード抑止 & 片手操作向け全タブ左右スワイプ遷移**
  - デモアプリ・通常モードともに「現在の日付の月（`new Date()` の年月）」まで表示・移動でき、現在の日付の月を表示中はヘッダーの「翌月（`▶`）」ボタンが `disabled` になり、カレンダーで現在の日付の月を表示中に左スワイプすると未来月ではなく「食品・活動」画面へ遷移すること。また、日次詳細ドロワーを下スワイプで閉じる際にブラウザのPull-to-Refresh（ページリロード）が発火せず滑らかにドロワーのみが閉じること。さらに、タブ切り替えおよびカレンダー月切り替えの両方で移動方向に連動した180msマイクロ・スライド＆フェードアニメーション（`.cgm-slide-fade-forward` / `.cgm-slide-fade-backward`）が横スクロール溢れなく滑らかに動作すること。
