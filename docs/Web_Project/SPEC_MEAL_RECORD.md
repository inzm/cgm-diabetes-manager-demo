# 食事・インスリン・活動 手動記録・編集モーダル 詳細仕様書 (SPEC_MEAL_RECORD.md)

本ドキュメントは、血糖値・食事・インスリン統合管理システム Web版における **「食事・インスリン・活動 手動記録・編集モーダル（`src/components/records/MealRecordModal.tsx`, `src/components/records/ActivityRecordModal.tsx`）」** の機能要件、UI設計、登録済み食品・活動リスト連動、タイムゾーン安全規約（`src/lib/dateUtils.ts`）、および受け入れ条件（DoD）を定めた仕様書（SSOT）です。
旧VBA資産（`legacy_vba/vba_exported/frmAddMealEvent.txt`, `frmAddEventData.txt`）の入力動線を継承しつつ、Web版の正規化DBスキーマ（`db.categories`, `db.food_master`, `db.event_master`, `db.user_settings`）およびユーザー目線・引き算の原則に準拠して策定されています。

---

## 1. 概要 & 目的

ユーザー（患者）が日々の生活の中で、
1. **基本情報（記録日時、現在時刻に応じた4区分自動初期選択：朝食・昼食・夕食・間食、およびインスリン投与量：空欄プレースホルダーまたは設定画面の区分別デフォルト値自動入力）**
2. **食事内容（「登録済みから選ぶ」モードでのカテゴリ・食品セレクトボックスと単位ラベル自動表示、「直接入力する」モード切替、追加後の数量インライン変更、糖質量自動合算）**
3. **活動・運動・イベント内容（よく使う活動からの選択による実施時間自動セット、自由入力、空欄プレースホルダーのインスリン欄、補足メモ）**
をスマートフォン・PC双方で視線の逆流なく上から下へ数秒で手動記録・編集・削除できるようにし、カレンダー・24H血糖推移グラフ・分析画面へリアルタイムに反映させるためのコア入力インターフェースです。

## 3. 機能要件 & 臨床算出アルゴリズム

### 3.1 基本情報ブロック（日時・食事4区分・インスリン投与量の統合 & デフォルト単位連動）
1. **食事タイミング4区分 (`timing_category`) と時刻連動初期選択**:
   - 選択肢は **`朝食` / `昼食` / `夕食` / `間食`** の4区分に統一する。
   - 新規記録時は、現在時刻（`HH:mm`）に応じて自動的に初期区分を選択する（`04:00〜10:29`: `朝食`、`10:30〜15:29`: `昼食`、`17:00〜21:59`: `夕食`、それ以外: `間食`）。
2. **インスリン投与量の上部統合・空欄プレースホルダー・区分別デフォルト値連動**:
   - 記録日時・食事区分と同じ最上部の基本情報エリアにインスリン投与量（単位: U）を配置し、食事の基本属性を1ブロックで完結させる。
   - 毎回手動で `'0'` を消去する無駄をなくすため、デフォルト値機能が無効（`enable_default_insulin === false`）または該当区分のデフォルト値が未設定の場合は、初期値を **空文字 `''`（`placeholder="0"`）** とする。
   - 設定画面（`db.user_settings`）で **「デフォルト値を有効にする（`enable_default_insulin === true`）」** がONになっている場合、新規記録モーダル起動時および食事区分ボタン（`朝食` / `昼食` / `夕食` / `間食`）の切り替え時（※ユーザーがインスリン欄を手動編集する前）に、その食事区分に対応するデフォルト単位数（`default_insulin_breakfast` / `default_insulin_lunch` / `default_insulin_dinner` / `default_insulin_snack`）を自動セットする（起動直後の非同期読込中に区分を切り替えた場合も最新の選択区分に対して正確に反映する）。
   - ※インスリン単体投与（食事を伴わない持効型インスリン等）は「活動・インスリン記録モーダル」で記録する。
3. **インスリン投与量が未入力（空欄）のまま保存ボタンが押された場合の確認ダイアログ**:
   - すべての食事区分（`朝食` / `昼食` / `夕食` / `間食`）において、インスリン投与量欄が空欄（`insulinUnits.trim() === ''`）のまま「記録を保存」ボタンが押された場合、カスタム確認ダイアログ（`src/components/common/ConfirmDialog.tsx`）で **「インスリン投与量が未入力です。0単位として保存しますか？」**（ボタン：「戻って入力する」／「0単位として保存」）を表示し、入力し忘れによる誤記録を防止する。

### 3.2 食品追加エリア & 食べた食品リスト（順方向レイアウト・ユーザー目線表現・未保存変更の破棄確認）
1. **配置順の最適化（入力 ➔ 結果リスト）**:
   - 「食品を追加」エリアを上、「食べた食品リスト（追加済み明細・合計糖質）」をその直下に配置し、食品を追加した結果を視線の逆流なく確認・微調整できるようにする。
2. **「登録済みから選ぶ」モード（デフォルト）と「直接入力する」モードの分離**:
   - **登録済みから選ぶモード**:
     - 「マスタ」という開発者用語や「①」「②」の冗長な番号ラベルを排除し、スマートフォンでタップしやすい高さ `42px` 以上のカテゴリ選択セレクトボックス（初期表示: `すべてのカテゴリ`）と、食品選択セレクトボックス（初期表示: `食品を選ぶ...`、全カテゴリ時は `<optgroup>` 見出し付き）を並べて表示する。
     - 食品選択時は冗長なテキスト入力欄を表示せず、**数量入力欄 ＋ 単位ラベル表示 ＋ 自動計算された糖質量表示 ＋「＋ リストに追加」ボタン** のみのシンプルな構成とする。
   - **直接入力するモード**:
     - 未登録の食品を記録する場合に切り替えて使用し、食品名入力、「✨ 糖質推定」ボタン（`estimateCarbsWithGemini`）、数量・単位・糖質(g)入力を表示する。
3. **食べた食品リストでのインライン数量変更 & 比例再計算**:
   - リストへ追加した後も数量（`amount`）をインライン変更でき、基準糖質から糖質量および合計糖質（`total_carbs`）をリアルタイムに比例再計算する：
     $$\text{糖質量 (g)} = \frac{\text{数量}}{\text{基準量}} \times \text{基準糖質}$$
4. **食べた食品リストが空（0品）の場合の保存ボタン無効化**:
   - `mealItems.length === 0` の場合、フッターの「記録を保存（変更を保存）」ボタンを `disabled`（非活性）とし、空の食事イベントが誤登録されることを防止する。
5. **未保存変更（Dirty Check）に基づく破棄確認・削除のカスタム確認ダイアログ (`src/components/common/ConfirmDialog.tsx`) & 背景タップ時の入力保護**:
   - ブラウザ標準の `window.confirm()` は使用せず、デザインシステムと統一されたカスタム確認ダイアログ（`src/components/common/ConfirmDialog.tsx`）を使用する。
   - モーダル外側のグレー背景をタップした際は、モーダルを閉じずに現在フォーカスされている入力要素（`document.activeElement`）の `.blur()` を呼び出し、スマートフォンのフリック入力キーボードのみをスマートに閉じる（誤タップによる入力消失を100%防止）。
   - モーダルを開いた時点の初期状態から入力内容（食品リスト、リストへ追加する前の食品選択・直接入力欄 `selectedMasterId` / `newFoodName` / `newCarbs`、日時、インスリン量、メモ等）に**変更がある場合（`isDirty === true`）のみ**、「キャンセル」または「✕（閉じる）」押下時に「入力データが破棄されます。よろしいですか？」の確認ダイアログを表示する（既存記録を編集で開いて何も変更せずに閉じた場合、または新規作成時に食事区分ボタンを切り替えただけの場合は確認を出さずに即座に閉じる）。
   - 既存イベントの「削除」ボタンを押した場合も、同様にカスタム確認ダイアログ（「キャンセル」／「削除する」）を表示する。

### 3.3 よく使う活動との連動 & 初期値プレースホルダー化 (`db.categories` where `target_type === 'event'` & `db.event_master`)
1. **カテゴリ絞り込みセレクトボックス & `optgroup` 連動**:
   - `db.categories`（`target_type === 'event'`）からカテゴリ一覧を動的に読み込み、スマートフォンでタップしやすい高さ `42px` 以上のセレクトボックス（初期表示: `すべてのカテゴリ`）として表示する。選択したカテゴリをイベントの `timing_category` としてセットするとともに、活動候補を絞り込む。
   - 活動選択セレクトボックス（初期表示: `活動を選ぶ（時間を自動入力）...`）側でも、「すべてのカテゴリ」選択時は `<optgroup label="カテゴリ名">` でグループ表示する。
2. **活動名およびインスリン投与量の初期値プレースホルダー化**:
   - 新規作成時は、活動名欄に特定の文字列（`'ウォーキング'` 等）をハードコードせず **空欄 `''`（`placeholder="例: ウォーキング 30分"`）** とし、インスリン投与量（任意）も **空欄 `''`（`placeholder="0"`）** とする。
   - 編集時または新規入力途中で変更がある場合（`isDirty === true`）に閉じるボタンを押した際は、未保存破棄の確認ダイアログを表示する。
3. **活動選択による自動入力**:
   - `db.event_master` から定型活動（例: ウォーキング 30分、ジョギング 20分、入浴 20分、持効型インスリン投与等）を選択すると、活動名（`event_name`）、実施時間（`default_duration` 分）、所属カテゴリ名、およびデフォルトメモが自動セットされる。
4. **活動名と補足メモの保存**:
   - 活動名と補足メモを組み合わせて `events.memo` に保存し、実施時間を `events.duration_minutes`、インスリン単位数を `events.insulin_units` に保存する。

### 3.4 タイムゾーン安全な日時保存 & 食前・食後血糖値バインドの責務分離 (`src/lib/dateUtils.ts`)
- **タイムゾーンズレの完全防止**:
  - 入力された日付（`YYYY-MM-DD`）と時刻（`HH:mm`）は、`new Date(...).toISOString()`（UTC変換による -9時間ズレが発生する）を使わず、必ず `buildWallClockIso(date, time)`（`src/lib/dateUtils.ts`）を用いて `"YYYY-MM-DDTHH:mm:00.000Z"` 形式で保存・検索する。
  - 編集時の日時復元も `extractDateStr(event.event_datetime)` および `extractTimeStr(event.event_datetime)` を用い、入力した時刻と1分の狂いもなく一致させる。
- **食前・食後血糖値バインドのCSV取込時への集約**:
  - 食事を記録する時点では当日のCGM履歴データ（CSV）はまだ取り込まれていないのが一般的な運用であるため、食事記録モーダルの保存時には `libre_readings` の検索・バインドを行わない。
  - 代わりに、後日リブレCSV履歴データを取り込んだ時点（[`SPEC_CSV_IMPORT.md`](file:///c:/Users/PC05/Documents/VBA/課題/anti_test/docs/Web_Project/SPEC_CSV_IMPORT.md) / `src/lib/anomalyExtractor.ts` の `bindMealGlucoseFromReadings`）および分析計算時に、履歴データから食前血糖値（`pre_meal_glucose`）と食後ピーク血糖値（`post_meal_glucose`）を自動バインドする。

### 3.5 データ永続化 (IndexedDB トランザクション & カスケード論理削除)
1. **新規作成 / 編集更新**:
   - `events` および `meal_details` を Dexie トランザクション内で原子的に保存。
2. **削除（カスケード論理削除）**:
   - `events.is_deleted = true` に更新し、紐づく `meal_details` の全レコードも連動して `is_deleted = true` に更新する。

### 3.6 ロール制約（家族閲覧ロール）・デモアプリ制御 & モーダル開閉アニメーション
- `isReadOnly === true`（家族アカウント・閲覧専用）の場合：
  - モーダル内の「保存」「削除」「食品追加」ボタンを物理的に非活性化（disabled）または非表示化。
- **デモアプリ（`isPortfolioMode()`）における糖質推定ボタンの非表示化**:
  - デモアプリでは、直接入力モード（「直接入力する」タブ）における「✨糖質推定」ボタンを非表示とする。
- **モーダル・確認ダイアログの開閉アニメーション**:
  - `MealRecordModal`、`ActivityRecordModal`、および `ConfirmDialog` はすべて2段階マウント制御により、オープン時は背景のフェードイン＋モーダル本体のズーム＆フェードイン（`cubic-bezier(0.16, 1, 0.3, 1)`）、クローズ時はフェードアウト＆縮小トランジションを実行してからアンマウントする。

## 4. 受け入れ基準 (Definition of Done: DoD)

- [x] **DoD-1: 基本情報の上部統合・順方向レイアウト・0品時の保存ボタン無効化**
  - 日時・食事区分（時刻連動初期選択）・インスリン投与量が最上部エリアにまとまり、「食品を追加」の下に「食べた食品リスト」が配置され、食品リストが空（0品）の場合は「記録を保存」ボタンが `disabled` になること。
- [x] **DoD-2: インスリン初期値の空欄化・区分別デフォルト値連動・未入力保存時の確認**
  - デフォルト値機能OFF時はインスリン欄が空欄（`placeholder="0"`）となり、ON時は選択された食事区分（朝・昼・夕・間食）のデフォルト単位数が自動入力され、空欄のまま保存ボタンを押した際は「インスリン投与量が未入力です。0単位として保存しますか？」の確認ダイアログが表示されること。
- [x] **DoD-3: 未保存変更（`isDirty`）に基づく破棄確認ダイアログ & 開発者用語の完全排除**
  - 初期状態から入力変更がある場合のみキャンセル・閉じる押下時に「入力データが破棄されます。よろしいですか？」の確認が表示され、モーダル内に「マスタ」等の開発者用語が一切表示されないこと。
- [x] **DoD-4: 食前血糖値バインドのCSV取込時への集約**
  - 食事記録モーダル保存時には全件走査を行わず、対象食事イベントの前後1日のみを `[user_id+timestamp]` 複合インデックスの `between()` で局所検索して食前・食後ピーク血糖値を即時紐づけし、CSV履歴データ取込完了時には日付バケットインデックスで一括自動バインドされること。
- [x] **DoD-5: 活動記録のよく使う活動連動 & 初期値プレースホルダー化**
  - 活動記録モーダルの活動名・インスリン欄の初期値が空欄プレースホルダーとなり、よく使う活動を選択すると活動名と標準実施時間（分）が自動セットされて保存できること。
- [x] **DoD-6: 家族ロール制約・デモアプリでの糖質推定ボタン非表示 & 型安全性・ビルド品質**
  - 家族閲覧ロール（`isReadOnly === true`）での登録・変更が不可侵に保護され、デモアプリ（`isPortfolioMode()`）では直接入力時の「糖質推定」ボタンが非表示となり、`npm run verify:all` がエラーゼロでパスすること。
