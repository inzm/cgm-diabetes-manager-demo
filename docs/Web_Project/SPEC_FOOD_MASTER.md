# よく使う食品・活動（旧イベント管理）詳細仕様書 (SPEC_FOOD_MASTER.md)

本ドキュメントは、血糖値・食事・インスリン統合管理システム Web版における **「よく使う食品・活動画面（`src/components/foods/FoodMasterView.tsx`, `src/components/foods/FoodCard.tsx`, `src/components/foods/FoodEditModal.tsx`, `src/components/foods/EventEditModal.tsx`, `src/components/foods/CategoryManageModal.tsx`）」および「糖質量自動推定エンジン（`src/lib/gemini.ts`, `src/lib/foodSeed.ts`）」** の機能要件、画面設計、記録モーダルとのデータ連携、および受け入れ条件（DoD）を定めた仕様書（SSOT）です。

---

## 1. 画面概要 & 目的

「よく使う食品・活動」画面は、日々の食事記録（`src/components/records/MealRecordModal.tsx`）および活動・インスリン記録（`src/components/records/ActivityRecordModal.tsx`）を数秒で入力できるようにするため、普段よく食べる食品やよく行う運動・活動を登録・整理しておく画面です。
「マスタ」などの開発者目線の言葉や不要な説明文・各行の重複ラベルを排除し、PCのサブナビゲーションおよびスマートフォンのボトムナビゲーションの **「食品・活動」** タブから共通でアクセスでき、以下の4つのデータを追加・編集・削除・一括整理できます：

1. **よく使う食品 (`db.food_master`)**: 食品名、基準分量、単位、糖質量(g)、所属食品カテゴリ（糖質量自動推定対応）
2. **食品カテゴリ (`db.categories` where `target_type === 'food'`)**: 主食、主菜、副菜、間食・デザート、飲料等のカテゴリ追加・編集・削除
3. **よく使う活動 (`db.event_master`)**: 運動・入浴・生活習慣・インスリン等の定型活動名、標準実施時間（分）、補足メモ、所属活動カテゴリ
4. **活動カテゴリ (`db.categories` where `target_type === 'event'`)**: 運動、生活・入浴、体調・補食、インスリン等のカテゴリ追加・編集・削除

本画面で登録・編集したデータは、`MealRecordModal.tsx` および `ActivityRecordModal.tsx` の選択リストにリアルタイムで反映されます。

### 2.1 リスト型UI & インタラクション仕様（引き算の法則と操作高速化）
1. **リスト型デザインと重複ラベル・小ボタンの排除 (`src/components/foods/FoodCard.tsx`, `src/components/foods/FoodMasterView.tsx`)**:
   - 各項目に毎回「基準分量:」「糖質量」といったラベルや小さな `[✎][🗑]` アイコンボタンを繰り返さず、縦一列に揃うリスト行形式で表示し、視線の垂直移動だけで糖質量や基準量を即座に比較できるようにする。
2. **行クリック／タップによるダイレクト編集**:
   - リスト行（チェックボックス領域を除く）をクリックまたはタップすると、直接編集モーダル（`FoodEditModal` / `EventEditModal`）が開く（`isReadOnly === true` の家族閲覧モード時は無効）。
3. **チェックボックスによる複数選択 & 一括削除・一括カテゴリ変更**:
   - 各行の左端およびリストヘッダー左端（表示中項目の全選択／全解除）にチェックボックスを配置する。
   - 1件以上選択すると、一括操作バー（`N件を選択中` ｜ `カテゴリ変更` セレクタ ｜ `一括削除` ボタン ｜ `選択解除`）が表示され、複数項目の一括カテゴリ移動および一括論理削除（`ConfirmDialog` 確認付き）を1トランザクションで実行できる。
4. **PC右サイド「カテゴリメニュー」とモバイル横スクロールピルのレスポンシブ構成**:
   - **PC表示（`lg` 以上）**: 2カラム構成とし、右サイドメニュー（Sticky追従）にカテゴリ一覧（件数バッジ付き）と「カテゴリを編集」ボタンを常時表示する。
   - **モバイル・タブレット表示（`lg` 未満）**: 縦画面領域を圧迫しないよう、検索バー下部に横スクロール可能なカテゴリピルと「カテゴリ編集」ボタンを配置する。
5. **列ヘッダークリックによる直感ソート**:
   - リスト見出しの `食品名 ↕` / `糖質量 ↕`（活動タブでは `活動名 ↕` / `標準時間 ↕`）をクリックすると、昇順・降順がワンクリックで切り替わる。

### 2.2 モーダル構成（ユーザー目線文言 & 編集モーダル内削除導線）
1. **食品登録・編集モーダル (`src/components/foods/FoodEditModal.tsx`)**:
   - 見出しはシンプルに「食品を登録」／「食品を編集」とし、冗長な副題は設けない。
   - 食品・料理名、基準分量、単位、カテゴリ、糖質量(g)（「✨ 糖質を自動推定」ボタン付き）を入力し、「保存する」ボタンで保存（モーダル入力中に親画面のカテゴリ配列参照が非同期更新されても入力中のテキスト・推定値がクリアされないよう制御）。
   - 既存食品の編集モード時は、フッター左側に「削除」ボタンを併設し、1件だけ内容を確認してから削除する操作にも対応する。
2. **活動登録・編集モーダル (`src/components/foods/EventEditModal.tsx`)**:
   - 見出しはシンプルに「活動を登録」／「活動を編集」とし、冗長な副題は設けない。
   - 活動名（例: ウォーキング、ジョギング、入浴、ブドウ糖補食等）、カテゴリ、標準実施時間（分）、補足メモを入力し、「保存する」ボタンで保存（入力中の親カテゴリ非同期ロード時に入力内容を保持）。
   - 既存活動の編集モード時は、フッター左側に「削除」ボタンを併設する。
3. **カテゴリ管理モーダル (`src/components/foods/CategoryManageModal.tsx`)**:
   - 見出しは「食品カテゴリ管理」／「活動カテゴリ管理」とし、不要な説明文は省く。
   - 一覧表示、新規カテゴリ追加、カテゴリ名称変更、および**カテゴリ削除（受け皿である「未分類」`is_protected === true` を除くすべてのカテゴリが削除可能）**を実行。
   - **カテゴリ削除時の「未分類」自動移動（孤児データ防止）**: いずれかのカテゴリを削除した際、そのカテゴリに所属していた食品（`db.food_master`）または活動（`db.event_master`）は削除せず、同一トランザクション内で自動的に「未分類」カテゴリへ付け替える。
4. **削除操作時のカスタム確認ダイアログ (`src/components/common/ConfirmDialog.tsx`) & モーダル開閉アニメーション**:
   - 単体削除・一括削除・カテゴリ削除時は、ブラウザ標準の `window.confirm()` を使わず、共通のカスタム確認ダイアログ（`src/components/common/ConfirmDialog.tsx`）で確認を行う（カテゴリ削除時は所属項目が「未分類」へ移動する旨を明記）。
   - `FoodEditModal`、`EventEditModal`、`CategoryManageModal`、および `ConfirmDialog` は2段階マウント制御により、開閉時に背景フェードとモーダル本体の滑らかなズーム＆フェードイン/アウトアニメーションを実行する。

## 3. 糖質量自動推定プロトコル (`src/lib/gemini.ts` — 方式1)

- 食品名、分量、単位から日本食品標準成分表に基づいて糖質量（`carbs_g`）を自動推定します。
- セキュリティ保護のため、フロントエンド（`localStorage`）にはAPIキーを一切保持せず、サーバーサイドBFFプロキシ（`/api/gemini`）が有効な場合はプロキシ経由、未接続時やオフライン時は内蔵の日本食品標準成分表辞書（`estimateCarbsLocally`）で安全かつ即座に推定値を返します。

  - スマートフォン表示（`sm` 未満、`375x812`）でも食品リストの12カラムグリッド配分を従来の `7 / 2 / 3` から `col-span-7（食品名）/ col-span-3（基準量）/ col-span-2（糖質量）`（モバイル・PC共通）に最適化し、`1 玉(250g)` や `1 小鉢(60g)` などのグラム表記が `...` で省略されず100%視認できるようにする。
  - `CategoryManageModal.tsx` のカテゴリ一覧コンテナ高さを `max-h-80`（`320px`）とし、初期7カテゴリすべてが文字見切れなく一覧表示されるようにする。また、`isOpen` または `targetType` が変化した際に `newCategoryName`, `editingId`, `editingName`, `errorMsg`, `deleteTargetCategory` をクリーンにリセットする。
  - **モーダル背景（グレー領域）タップ時の入力保持＆キーボード収納と `isDirty` 破棄確認ダイアログ (`FoodEditModal.tsx`, `EventEditModal.tsx`, `CategoryManageModal.tsx`)**:
    - スマートフォンでフリック入力キーボードが開いている状態でモーダル外側のグレー背景をタップした際、誤ってモーダルが閉じて入力内容が消失しないよう、背景オーバーレイタップではモーダルを閉じず、現在フォーカスされている入力要素（`document.activeElement`）の `.blur()` を呼び出してソフトウェアキーボードのみをスマートに閉じる。
    - オープン時の初期値から変更がある場合（`isDirty === true`）に `[✕]` または `[キャンセル]` / `[閉じる]` を押下した際は、`ConfirmDialog`（タイトル: `入力データの破棄確認`、メッセージ: `入力中の内容が保存されていません。破棄して閉じてもよろしいですか？`）を表示して誤消去を防止する。
  - デモアプリ（`isPortfolioMode()`）では、`FoodEditModal.tsx` 内の「✨糖質を自動推定」ボタンを非表示とする。また、デモアプリでのリロード時および設定画面からの手動リセット時には、`resetFoodSeedSession` および `resetFoodAndEventMasterToInitial`（`src/lib/foodSeed.ts`）により、`food_master`・`event_master`・`categories` も初期シード状態（`INITIAL_FOODS`, `INITIAL_EVENTS`, `INITIAL_CATEGORIES`）へ100%リセットする。また、`src/lib/gemini.ts` の `estimateCarbsLocally` は `INITIAL_FOODS` の定義値を最優先で参照し、複合料理名（「焼きそば」「肉まん」「水ようかん」「カレーパン」「いちご大福」等）の部分一致優先順位を厳密に保証する。
